# Αποφάσεις & Ανοιχτά Ερωτήματα

Ημερολόγιο σχεδιαστικών αποφάσεων για το προσωπικό portfolio site.
✅ = κλειδωμένο, ❓ = ανοιχτό προς συζήτηση.

---

## ✅ D1 — Tech stack
**Next.js 16 (App Router) + TypeScript + Tailwind 4 + MDX**, με στατική παραγωγή (SSG).

Λόγοι:
- Το ίδιο stack με το duty-scheduler → μηδενικός χρόνος μάθησης, άμεση παραγωγικότητα.
- Το site γίνεται και το ίδιο δείγμα δουλειάς: ο κώδικάς του είναι public.
- SSG = καμία βάση, κανένας server, μηδενικό κόστος, άριστο Lighthouse.

Δεν υπάρχει backend, δεν υπάρχει βάση. Όλο το περιεχόμενο ζει σε αρχεία μέσα στο repo.

## ✅ D2 — Public repo
Το repo είναι **δημόσιο**. Ένα portfolio του οποίου ο κώδικας κρύβεται στέλνει λάθος
μήνυμα — εδώ ο κώδικας είναι μέρος του επιχειρήματος.

Συνέπεια: τίποτα ευαίσθητο δεν μπαίνει ποτέ στο repo (βλ. **D9**).

## ✅ D3 — Hosting: Vercel
Ξεκινάμε με το δωρεάν `*.vercel.app`. Custom domain (π.χ. `oikonomou.dev`, ~12€/έτος)
δένει αργότερα **χωρίς καμία αλλαγή στον κώδικα** — μόνο ρύθμιση DNS.

Γιατί Vercel και όχι GitHub Pages: preview deployment ανά branch (βλέπεις κάθε αλλαγή
σε πραγματικό URL πριν βγει δημόσια) και μηδενική ρύθμιση για Next.js.

## ✅ D4 — Δίγλωσσο EN/GR
Routes με prefix locale: `/en/...` και `/el/...`. Default το **EN** (το `/` κάνει
redirect στο `/en`). Διακόπτης γλώσσας στο header, διατηρεί τη σελίδα στην οποία είσαι.

Μεταφράσεις UI σε `messages/en.json` + `messages/el.json`. Περιεχόμενο project: δύο
αρχεία ανά project (`slug.en.mdx`, `slug.el.mdx`).

**Κόστος που δεχόμαστε συνειδητά:** κάθε κείμενο γράφεται δύο φορές, για πάντα.
Αν κάποιο project δεν έχει ελληνική εκδοχή, η σελίδα πέφτει πίσω στην αγγλική με
διακριτική ένδειξη — δεν σπάει το build.

## ✅ D5 — Κοινό & τόνος
**Κύριο:** προσωπική βιτρίνα — μόνιμη, καλοφτιαγμένη παρουσία.
**Δευτερεύον:** εργοδότες εξωτερικού (remote) και freelance πελάτες.

Πρακτικές συνέπειες:
- Τόνος πρώτου προσώπου, χωρίς εταιρικό marketing-speak.
- Κάθε project απαντά σε τρία πράγματα: *τι πρόβλημα*, *τι έφτιαξα*, *τι πέτυχε*.
- Διακριτικό «Open to work / Available for freelance» στο footer και στο `/contact` —
  όχι κραυγαλέο banner στην αρχική. Μπορεί να ανάβει/σβήνει από ένα flag.
- Καμία τιμολόγηση, καμία λίστα «υπηρεσιών» — δεν είναι site εταιρείας.

## ✅ D6 — Content model: αρχεία, όχι CMS
Κάθε project = ένα MDX αρχείο με τυποποιημένο frontmatter. Το schema επικυρώνεται με
**zod** στο build — λάθος ή ελλιπές frontmatter ρίχνει το build, δεν περνά σιωπηλά.

Οι κατηγορίες, τα φίλτρα και οι σελίδες τεχνολογιών **παράγονται από τα δεδομένα**.
Δεν υπάρχει χειροκίνητη λίστα κατηγοριών πουθενά.

Νέο project = νέο αρχείο + commit. Καμία βάση, κανένα admin panel, μηδενικό κόστος.

## ✅ D7 — CV: ένα σημείο αλήθειας, αυτόματο PDF
Τα δεδομένα του βιογραφικού ζουν σε **ένα** typed αρχείο (`content/cv.ts`). Από εκεί
τρέφονται δύο πράγματα:
1. Η σελίδα `/cv` (HTML, διαβάζεται online, γίνεται index από Google).
2. Τα `public/cv-en.pdf` και `public/cv-el.pdf`.

Η παραγωγή γίνεται με `@react-pdf/renderer` μέσω `npm run cv:pdf`, **τοπικά**, και τα
PDF γίνονται commit. Δεν τρέχει headless browser στο build του Vercel — λιγότερα
κινούμενα μέρη, ντετερμινιστικό αποτέλεσμα, και το PDF μπορεί να ελεγχθεί οπτικά
πριν φύγει.

Έλεγχος στο CI: αν αλλάξει το `cv.ts` και δεν έχουν ξαναπαραχθεί τα PDF, το build
προειδοποιεί.

## ✅ D8 — Design: δικό μας, όχι template
Χτίζουμε μικρό design system (τυπογραφία, χρωματική κλίμακα, spacing, components)
πριν γραφτεί σελίδα. Dark mode από την πρώτη μέρα, με σεβασμό στο `prefers-color-scheme`
και χειροκίνητο διακόπτη.

Κανένα έτοιμο portfolio template. Ένα portfolio προγραμματιστή που μοιάζει με τα άλλα
χίλια δεν αποδεικνύει τίποτα.

## ✅ D9 — Ιδιωτικότητα & ευαίσθητα δεδομένα (κρίσιμο)
Αρκετά από τα project σου αγγίζουν πραγματικά, ευαίσθητα δεδομένα: στρατιωτικά
έγγραφα, μισθοδοσία, ΑΑΔΕ, τραπεζικά (Open Banking), ονόματα προμηθευτών.

**Κανόνες, χωρίς εξαίρεση:**
- Κανένα screenshot με πραγματικά ονόματα, ΑΦΜ, ποσά ή αριθμούς εγγράφων.
  Κάθε εικόνα είτε ανωνυμοποιείται είτε τραβιέται από seed/ψευδοδεδομένα.
- Καμία αναφορά σε συγκεκριμένη μονάδα, φορέα ή πελάτη χωρίς ρητή άδεια.
  Γράφουμε «δημόσιος φορέας», «εταιρεία ενέργειας» κ.ο.κ.
- Κανένα API key, token, credential, connection string — ούτε σε screenshot,
  ούτε σε παράδειγμα κώδικα. Έλεγχος με secret scanning πριν το πρώτο public push.
- Για project που δεν μπορούν να ανοίξουν: παρουσιάζονται ως **case study χωρίς repo**.
  Η περιγραφή του προβλήματος και της λύσης έχει την ίδια αξία με τον κώδικα.

## ✅ D10 — Analytics χωρίς cookies

## ❓ Ανοιχτά

### ❓ D11 — Custom domain
Ποιο όνομα; Προτάσεις: `oikonomou.dev`, `vasilisoikonomou.com`, `boikonomou.dev`.
Απόφαση μπορεί να πάρει χρόνο — δεν μπλοκάρει τίποτα.

### ❓ D12 — Blog / γραπτά
Αξίζει ενότητα `/blog` ή `/notes`; Ένα-δύο καλά τεχνικά κείμενα ανεβάζουν πολύ ένα
portfolio, αλλά ένα εγκαταλελειμμένο blog με ένα post του 2026 το ρίχνει.
Πρόταση: **όχι στην πρώτη έκδοση**, ξανασυζήτηση αφού βγει το site.

### ❓ D13 — Φόρμα επικοινωνίας
Φόρμα (χρειάζεται endpoint + anti-spam) ή απλό `mailto:` + social links;
Πρόταση: **mailto + links** στην πρώτη έκδοση, μένει 100% στατικό.
